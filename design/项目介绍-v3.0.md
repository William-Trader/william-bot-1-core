文档版本 v3.0 ｜ 生成日期 2026-09-26 ｜ 运行主机 101（Ubuntu · 2 核 / 1.6 GB）

## 一、项目概述

威廉机器人 1 号是一套部署在云端服务器（下称"101"）上的全自动量化交易系统，交易标的为 OKX 永续合约（USDT 本位 SWAP），采用"类马丁"篮子结构：首单按风险预算开仓，价格不利时按固定间距加层摊低成本，价格有利时整篮止盈，并用多层硬边界控制尾部亏损。

与经典马丁的区别在于：**每层暴露、每篮风险、同向总风险、单日亏损都有硬上限**，且所有边界都可在参数面板调整、可回测验证。

### 1.2 设计铁律（不可协商）

- 默认仿真：任何下单路径未显式 LIVE=1 时不得发出真实订单。
- 无未来函数：信号与指标只用"上一根及更早"的已收盘数据。
- 回测成本口径：10 bps 往返手续费 + 5 bps 单边滑点，并计入真实资金费率。
- 期望为负就如实报告，不为了"能上线"而调参粉饰。
- 涉及仓位必须能算出预估强平价与最大亏损；密钥只留在服务器 600 权限文件内，不进前端与日志。

## 二、系统架构

### 2.1 组件与端口

| 组件 | 单元 / 路径 | 监听 | 职责 |
| --- | --- | --- | --- |
| 交易底座 | william-bot-1 | 127.0.0.1:3100 | 行情拉取、下单执行、HTTP 接口与交易面板 |
| 策略调度器 | wb-core-scheduler | 无 | 每 30 秒巡检篮子、每 5 分钟全市场选品、每日 00:05 日结 |
| 消息推送 | wb-qq-push | 无 | 事件推送到 QQ 群（直连官方 API，约 1.8 秒/条） |
| 网络看门狗 | wb-net-guard.timer | 无 | 每 2 分钟探测 OKX，不通则自动切换代理节点 |
| 每日验算 | wb-core-verify.timer | 无 | 每日 00:11 生成实盘与回测的对账报告 |
| 每日备份 | wb-core-backup.timer | 无 | 每日 04:30 备份关键数据 |
| 压力监控 | wb-health.timer | 无 | 定期检查大盘压力与数据质量 |

### 2.2 决策链路

1. 选品：全市场扫描，按波动率与趋势特征给出候选与允许方向。
2. 闸门：逐项检查（熔断、方向风险、资金费率、ATR 区间、板块与品种去重、入场状态过滤、保证金可行性）。
3. 开仓：按"风险预算"反推首单张数，确保到止损的最大亏损等于预算。
4. 加仓：价格按固定间距（ATR 倍数）不利推进时加层，最多到层数上限。
5. 止盈：整篮止盈（ATR 口径，带下限）＋ 部分止盈（浮盈达阈值先平一半）。
6. 止损：死亡线（ATR 倍数）／硬止损（百分比）／金额兜底／时间止损，四者先到先执行。
7. 对账：每轮用交易所真实持仓校正本地账本（张数、保证金、均价、强平价），异常自动归档。
8. 日结：每日一条记录，盈亏按"权益差（剔除出入金）"口径。

### 2.3 目录与规模

- modules/：策略引擎、调度、风控、交易、行情、存储（零 npm 依赖）
- scripts/：回测、验算、推送、守护类脚本
- public/：单页交易面板（深色主题，含可视化图表）
- data/：状态、参数、候选池、验算报告、备份

## 三、策略机制

| 环节 | 当前规则 |
| --- | --- |
| 选品过滤 | 波动率特征（vr5）低于阈值才允许开首单；趋势过强不入场 |
| 首单风险 | 到止损的最大亏损 = 权益 × 2% |
| 加仓间距 | ATR × 1.0（可按参数调整） |
| 加仓倍数 | 1.5 倍（每层比上一层大 50%） |
| 层数上限 | 2 层（暴露 = 首层 × 2.5） |
| 整篮止盈 | ATR × 0.5，下限 0.4%（以市价成交，保证确定性） |
| 部分止盈 | 浮盈 +0.8% 先平 50%，降低暴露 |
| 死亡线止损 | 5 × ATR |
| 硬止损 | 3% |
| 金额兜底 | 单篮 1.5% |
| 时间止损 | 48 小时 |
| 趋势反转 | 确认反向趋势（趋势态明确相反）→ 立即整篮平仓 |
| 冷却 | 平仓后同品种 4 小时不开新仓 |

## 四、风控体系（四层硬边界）

| 层级 | 边界 | 当前值 | 说明 |
| --- | --- | --- | --- |
| 单篮 | 到止损风险 | 权益 × 2%（约 9.75 U） | 由风险预算反推张数 |
| 单篮 | 层数 | 2 层 | 旧值 4 层，暴露为首层的 8 倍 |
| 同向 | 总风险 | 权益 × 10%（约 48.75 U） | 同一方向所有篮子到止损亏损之和 |
| 全局 | 日亏熔断 | 5%（约 24.4 U） | 触发后停止开新仓 |
| 辅助 | 主动降险 | 超阈值 + 市场承压 → 减半 | 仅对新开有限制时不足以止血 |
| 辅助 | 对账与归档 | 每轮 | 幽灵仓自动认领/归档、孤儿挂单撤销 |

### 5.2 重灾日复盘（2026-09-23 / 09-24）

四个巨亏篮子，形态完全一致：

| 时间 | 品种 | 方向 | 层数 | 亏损 |
| --- | --- | --- | --- | --- |
| 09-23 22:10 | TRUMP | 多 | 4 / 4 | −19.89 |
| 09-23 22:13 | ASTER | 多 | 4 / 4 | −18.98 |
| 09-24 10:04 | WLD | 多 | 4 / 4 | −18.30 |
| 09-24 16:04 | ARB | 多 | 4 / 4 | −9.31 |

**结论：这 4 笔占全部亏损的 100%**（其余数十笔合计约 +2.9）。共同特征为"单边做多 + 叠满 4 层 + 趋势反转 → 触发止损"，每笔约 −3.9% 权益。

根因有两条：
1. 层数快照：全局层数上限已下调，但在库篮子仍持有开仓时的旧快照（4 层），加仓判定用的是篮子自带政策，于是继续加满。
2. 暴露倍数：4 层满仓的名义暴露约为首层的 8 倍，一次反转即被打穿。

### 5.3 对应修复（本次迭代）

| 修复项 | 内容 |
| --- | --- |
| 限层 | 层数上限 3 → 2；并把在库篮子的层数快照统一迁移为 2 |
| 死亡线 | 6 × ATR → 5 × ATR |
| 趋势反转 | 只减半 → 确认反向立即整篮平仓 |
| 杠杆 | 5 倍 → 3 倍 |
| 并发篮子 | 10 → 5 |
| 单篮风险 | 权益 4% → 2% |
| 同向上限 | 权益 8% → 10%（配合单篮减半，使每方向可容约 5 篮） |
| 止盈方式 | 限价挂单 → 市价（限价实测成交率仅 59%，低于平衡线 85%） |
| 日结 | 改为每日一条（消除同日多条冲突记录） |
| 归因 | 平仓归因改用交易所记录（不再依赖挂单，市价止盈也能正确归因为正常离场） |
| 推送 | 交易类事件去重窗口 6 小时 → 60 秒；同因拦截聚合，避免刷屏与漏推 |
| 幽灵仓 | 浮盈达阈值自动兑现、无利可图则认领纳入风控；孤儿挂单自动撤销 |

### 6.2 层数敏感性（说明限层为何最关键）

| 变体 | 单笔期望 | 止损次数 | 胜率 |
| --- | --- | --- | --- |
| 2 层（当前） | 基准 | 基准 | 基准 |
| 4 层 | −75.7% | 约 3 倍（17 → 48） | −2.5 个百分点 |

### 6.3 趋势反转处理对比

| 模式 | 单笔期望 | 回撤 |
| --- | --- | --- |
| 立即全平（当前采用） | 2.15 bps | −11.99% |
| 确认后全平 | 2.25 bps | −10.98% |
| 减半持有 | 2.70 bps | −9.19% |

即：减半模式在回测中期望更高，但实盘巨亏全部发生在"减半留半仓"期间，且其最大单笔亏损更大；本版本选择"立即全平"以优先控制尾部。

### 6.4 成本实测

| 项目 | 实测 | 回测假设 |
| --- | --- | --- |
| 手续费（单边） | 4.94 bps | 5 bps |
| 滑点 | −2.7 至 −6.3 bps（优于假设） | 5 bps |
| 资金费 | 约 ±0.03 U（可忽略） | 计入 |

### 6.5 实盘样本

- 9/25 参数重构后至 9/26：在仓全部不超过 2 层，未出现满层，未触发风控止损。
- 9/26 当日：平仓 22 笔，已实现 +5.26 U，手续费 −0.69 U，全天净 +3.63 U。

### 6.6 诚实的局限

- 滑点与成本结论的样本量偏小（匹配成交常低于 20 笔），方向可信、数值仅供参考。
- 策略结构决定其收益形态为"高胜率、单笔小、尾部重"，稳定盈利必须靠足够样本验证，不能用参数感觉代替。
- 回测使用 350 天 8 标的，与实际 20+ 标的、单账户小资金的运行环境存在量级差异。

## 八、已知限制与路线图

### 8.1 已知限制

1. 代理独立性：主通路为服务器本机代理，备用通路依赖本机中继，仍建议更换为可直连 OKX 的订阅。
2. 限价止盈：实测成交率低于盈亏平衡线，当前采用市价止盈；贴盘口挂单能力已实现但默认关闭。
3. 样本量：参数重构后的实盘样本仍偏少，不足以断言长期稳定盈利。
4. 最小下单量：小资金叠加合约整张下限，实际首层风险可能高于设计比例。

### 8.2 路线图

1. 保持当前小仓位跑满 30 至 50 笔，用真实数据复算期望、盈亏比与止损率。
2. 达标线：单笔期望为正（含成本）、无单笔亏损超过权益 2%、盈亏比大于 1.2、分段结果一致。
3. 达标后开放"贴盘口挂单"试点（先一半品种），实测成交率达到 85% 以上再全量。
4. 放大顺序：先提并发篮子上限，再提杠杆，最后才提单篮风险；每次只动一个变量并观察 24 小时。
5. 完成代理通路独立化。
